# Sandbox de mutation testing

> **Para o executor Nexo:** aplique uma mudança mecânica e use a asserção Node abaixo como oráculo bloqueado.

**Goal:** Excluir os dois mirrors locais de skills da cópia do sandbox Stryker sem alterar o conjunto ou a execução dos mutantes.

**Architecture:** `ignorePatterns` controla somente quais arquivos são copiados para o sandbox, enquanto `mutate` continua controlando os arquivos instrumentados.
Os padrões começam com `/` para serem relativos à raiz do repositório conforme o schema local do Stryker.

**Tech Stack:** StrykerJS, configuração ECMAScript module, Node.js e ESLint.

**Spec:** `nexo/runs/2026-08-26-attendance-by-class/verify-feature-mutation.md` e `node_modules/@stryker-mutator/core/schema/stryker-schema.json` na propriedade `ignorePatterns`.

## Causa provada

O primeiro boundary instrumentou 502 mutantes nos cinco alvos configurados e caiu antes da avaliação ao copiar `.claude/skills/migrate-radix-to-base` para o sandbox.
Esse caminho é um symlink para `.agents/skills/migrate-radix-to-base` e não é necessário ao Vitest nem aos arquivos em `src`.
O schema local confirma que padrões iniciados por `/` são relativos ao diretório corrente do Stryker.

## Oráculo bloqueado

O oráculo importa a configuração real, fixa exatamente os cinco alvos atuais e fixa todas as opções existentes junto das duas novas exclusões.

```bash
node --input-type=module <<'NODE'
import assert from "node:assert/strict";

const { default: config } = await import("./stryker.config.mjs");

assert.deepStrictEqual(config.mutate, [
  "src/features/fechamento/domain.ts",
  "src/features/pecas/domain.ts",
  "src/features/visao-geral/domain.ts",
  "src/features/relatorios/attendance-domain.ts",
  "src/features/relatorios/attendance-api.ts",
]);
assert.deepStrictEqual(
  config.ignorePatterns,
  ["/.agents", "/.claude"],
  "ignorePatterns must contain exactly the two root-relative skill mirrors",
);
assert.strictEqual(config.testRunner, "vitest");
assert.deepStrictEqual(config.reporters, ["clear-text", "progress"]);
assert.strictEqual(config.concurrency, 2);
assert.strictEqual(config.allowConsoleColors, false);
assert.deepStrictEqual(Object.keys(config).sort(), [
  "allowConsoleColors",
  "concurrency",
  "ignorePatterns",
  "mutate",
  "reporters",
  "testRunner",
]);
NODE
```

## Gate 2 da slice

assert.strictEqual(config.testRunner, "vitest");
assert.deepStrictEqual(config.reporters, ["clear-text", "progress"]);
assert.strictEqual(config.concurrency, 2);
assert.strictEqual(config.allowConsoleColors, false);
assert.deepStrictEqual(Object.keys(config).sort(), [
  "allowConsoleColors",
  "concurrency",

  "reporters",

npx eslint stryker.config.mjs --max-warnings=0

base="$(git merge-base main HEAD)"
git diff --check "$base" HEAD -- stryker.config.mjs
test "$(git diff --name-only "$base" HEAD)" = "stryker.config.mjs"
git diff --exit-code "$base" HEAD -- . ':(exclude)stryker.config.mjs'

test -z "$(ps -axo comm=,args= | awk '$1 ~ /(^|\/)node$/ && ($0 ~ /stryker/ || $0 ~ /vitest/) { print }')"

O diff protegido deve cobrir todo o repositório fora de `stryker.config.mjs` e deve permanecer vazio.
PASS exige os cinco alvos exatos, somente `/.agents` e `/.claude` em `ignorePatterns`, nenhuma exclusão de `src`, testes unitários ou arquivos necessários ao Vitest, ESLint verde, nenhum outro arquivo alterado e nenhum processo Stryker ou Vitest residual.
O dev server Vite preexistente não casa porque o predicado exige `stryker` ou `vitest` nos argumentos de um executável Node.
O executor e o Gate 2 não executam `npm run test:mutation`.
